Part 4 · The request · recall from 0.8

The service behind step four

BalanceService.swift
struct BalanceService {
    func fetchBalance() async throws -> Balance {
        let url = URL(string: "https://api.npay.example/balance")!
        let (data, response) = try await URLSession.shared.data(from: url)
        guard let http = response as? HTTPURLResponse,
              (200..<300).contains(http.statusCode) else {
            throw URLError(.badServerResponse)
        }
        return try JSONDecoder().decode(Balance.self, from: data)
    }
}

Fictional URL. Real banking code also needs authentication and secure token handling.

await suspendsthe main thread stays free
Any 2xx is success200..<300, not only 200
DecodeJSON → Balance
SAY

This is step four from Lesson 0.8, not new material. The service builds the URL, awaits URLSession, which suspends the task without blocking the main thread, accepts any 2xx status, and decodes the JSON into a Balance. The URL is fictional; real code also needs authentication, authorization-aware error handling and secure token management.

From active to terminated

MomentScene phaseProcessWhat it means

SAY

A recall from Lesson 0.3, so the whole table at once. Active: visible and responding. Inactive: still in the foreground but not receiving events. Background: no longer visible, execution may continue briefly. Suspended: kept in memory, no code runs. Terminated: the process is gone. One possible progression; iOS does not guarantee every app passes through each state in order.

SAY

Click: the three scene phases are active, inactive and background. Suspended describes the process. This matters when someone asks whether their background code keeps running.

Part 9 · Ownership · recall from 0.6

A ViewModel and its closure

A stored closure that strongly captures the ViewModel creates a retain cycle. [weak self] avoids it.

TransactionViewModel.swift
@MainActor
final class TransactionViewModel {
    var onRefresh: (() -> Void)?

    func configure() {
        onRefresh = { [weak self] in self?.refresh() }
    }

    func refresh() { print("Refreshing transactions") }

    deinit { print("ViewModel deinitialized") }
}
SAY

A recall from Lesson 0.6. The view owns the ViewModel, which uses the service. If the ViewModel stores a closure that strongly captures the ViewModel, a retain cycle can form; this code uses weak capture to avoid it.

ASK

Does navigating away from a screen guarantee its ViewModel’s deinit runs immediately?

EXPECT

No. It may still be legitimately retained elsewhere. Navigation and object lifetime are related but not identical.

Survived, or terminated?

Part 10 · Return scenarios

Warm activation or cold launch

Process survived: warm activation
  1. iOS resumes execution if the process was suspended.
  2. The scene returns toward the foreground.
  3. In-memory state may still exist.
  4. The app refreshes data when appropriate.
Process terminated: cold launch
  1. iOS starts a new process.
  2. The launch runs again, as in Stage one.
  3. In-memory state is gone.
  4. The app restores persisted data and fetches fresh data.
Work correctly in both. Never assume the process stays alive, and never assume cached financial data is current.
SAY

Warm activation: iOS resumes the suspended process, the scene comes back to the foreground, in-memory state may still exist, and the app refreshes data when appropriate. Click: cold launch: a new process, the full launch again, in-memory state is gone, so the app restores what it persisted and fetches fresh data.

SAY

A robust app must work in both cases. Never assume the process stays alive, and never assume cached financial data is current.

Problem

Common trap: Assuming async UI frameworks protect you from blocking code.
