Part 3 · SceneDelegate

A UIKit SceneDelegate

SceneDelegate.swift
import UIKit

class SceneDelegate: UIResponder, UIWindowSceneDelegate {
    var window: UIWindow?   // this scene's window

    func sceneDidBecomeActive(_ scene: UIScene)    { print("Active") }
    func sceneWillResignActive(_ scene: UIScene)   { print("Inactive") }
    func sceneDidEnterBackground(_ scene: UIScene) { print("Background") }
}
1sceneDidBecomeActivethe scene is ready for interaction
2sceneWillResignActivethe scene is about to become inactive
3sceneDidEnterBackgroundthe scene is no longer visible
Apple is making the scene life cycle mandatory for UIKit apps (TN3187). An AppDelegate-only app is legacy code to migrate.
SAY

Each callback is about one scene, not the whole app: it became active, it is about to resign active, it entered the background. The window property belongs to that scene.

SAY

This shows the callbacks, not the complete configuration a traditional UIKit scene-based project requires.

SAY

Scenes are not optional extras. Apple Technical Note TN3187 says that, in the release following iOS 26, UIKit apps built with the latest SDK must adopt the scene-based life cycle. If you inherit an AppDelegate-only app, plan its migration. (Authored addition from the Unit 00 audit.)

Part 4 · scenePhase

Observing scene changes

DashboardView.swift
struct DashboardView: View {
    @Environment(\.scenePhase) private var scenePhase

    var body: some View {
        Text("NPay Dashboard")
            .onChange(of: scenePhase) { _, phase in
                switch phase {
                case .active:     print("Active")
                case .inactive:   print("Inactive")
                case .background: print("Background")
                @unknown default: break
                }
            }
    }
}
1Read scenePhasefrom the environment
2onChangeruns when the phase changes
3Switch on the phase.active, .inactive, .background
The scenePhase environment value lets SwiftUI code respond to scene lifecycle changes.
SAY

The view reads scenePhase from the environment and reacts with onChange. Each case maps to a scene state from Lesson 0.3. @unknown default keeps the switch safe if Apple adds a phase.

CONNECT

But which scene is this phase about? It depends where you read it.

Part 4 · Where you read it

scenePhase in a View vs in the App

Read inYou get
a Viewthe phase of that view’s scene
the Appall scenes combined: active if any scene is active; background only when every scene is in the background
Per-screen work (pause this screen’s timer) belongs in the View; app-wide work (lock NPay when every window leaves) belongs in the App.
SAY

Click through. Window A is in front: a view inside it reads .active. Window B is in the background: a view inside it reads .background. The App reads the combined value: .active, because at least one scene is active. It only reports .background when every scene is in the background.

SAY

So per-screen reactions go in the view, and app-wide reactions, such as locking NPay when every window has left the screen, go in the App.

Part 7 · Delegate adaptor

UIApplicationDelegateAdaptor

NPayApp.swift
import SwiftUI

// AppDelegate: an ordinary class conforming to
// UIApplicationDelegate (no @main of its own)

@main
struct NPayApp: App {
    @UIApplicationDelegateAdaptor(AppDelegate.self)
    var appDelegate

    var body: some Scene {
        WindowGroup { DashboardView() }
    }
}
1A plain AppDelegateconforms to UIApplicationDelegate
2@UIApplicationDelegateAdaptorSwiftUI creates it and forwards delegate calls
3The App stays SwiftUIWindowGroup and views as usual
A modern SwiftUI structure, plus UIKit application delegate functionality where it is needed.
SAY

The AppDelegate is an ordinary class conforming to UIApplicationDelegate. The App declares @UIApplicationDelegateAdaptor, and SwiftUI creates that delegate and forwards application delegate calls to it. Everything else stays SwiftUI.

SAY

This is how you keep a modern SwiftUI structure while integrating UIKit application delegate functionality that some system integrations require.

Part 8 · Choosing

Which approach, when?

SAY

New application: start with the SwiftUI App lifecycle unless there is a specific reason not to; add the delegate adaptor only where an integration needs it. Existing UIKit application: understand and maintain AppDelegate, SceneDelegate and view-controller lifecycle behavior, and if it is still AppDelegate-only, plan the move to scenes. Hybrid: use interoperability, adapting the delegate where required; Unit 10 covers interoperability in depth.

What to remember

Each scene has its own lifecycleUIKit: SceneDelegate · SwiftUI: scenePhase
