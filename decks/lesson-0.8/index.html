Part 6 · URLSession

Fetching the balance

BalanceService.swift
import Foundation

func fetchBalance() async throws -> Data {
    let url = URL(
        string: "https://api.npay.example/balance"
    )!

    let (data, response) =
        try await URLSession.shared.data(from: url)

    guard let httpResponse = response as? HTTPURLResponse,
          httpResponse.statusCode == 200 else {
        throw URLError(.badServerResponse)
    }

    return data
}

The URL is fictional; no production authentication or validation beyond the status check.

1Create the URL
2Ask URLSessionto perform the request
3Suspend at awaitwhile the operation is pending
4Receivethe response or an error
5Validatethe response
6Returnthe data
SAY

Six steps: create the URL, ask URLSession to perform the request, suspend at await while it is pending, receive the response or an error, validate the response, and return the data.

ASK

EXPECT

No. The asynchronous task suspends while the networking operation proceeds, as in Lesson 0.5.

Decoding the balance

response.json

BalanceResponse.swift
struct BalanceResponse: Decodable {
    let accountId: String
    let currency: String
    let balanceMinor: Int64
}

let response = try JSONDecoder().decode(
    BalanceResponse.self,
    from: data
)
balanceMinor is in the smallest currency unit: 2,500,000 paise is ₹25,000. Integer minor units avoid floating-point errors in money.
SAY

The JSON has an account ID, a currency and balanceMinor, the amount in the smallest unit. For INR, 2,500,000 paise is ₹25,000. A Decodable struct with matching properties, and JSONDecoder turns the bytes into a BalanceResponse.

SAY

Integer minor units, or an appropriate decimal type, avoid the floating-point issues that are dangerous in financial calculations.

Part 8 · MVVM · conceptual

A ViewModel in the request path

A teaching skeleton: the networking service is intentionally not implemented.

BalanceViewModel.swift
import Foundation
import Observation

@MainActor
@Observable
final class BalanceViewModel {

    var balanceText = "—"
    var isLoading = false
    var errorMessage: String?

    func loadBalance() async {
        isLoading = true
        defer { isLoading = false }

        do {
            // Call an injected networking service.
            // Decode the response and format the balance.
            balanceText = "₹25,000"
        } catch {
            errorMessage = error.localizedDescription
        }
    }
}
SAY

Click down: the view displays the balance and loading state; the ViewModel coordinates the API call and updates observable state; the service uses URLSession and decodes; the server returns authorized account information.

SAY

The ViewModel is @MainActor and @Observable: it sets isLoading, uses defer to clear it however the function exits, and on error stores a message. The networking service call is a comment on purpose; this is a skeleton.

Part 9 · Failure explorer · illustrative

Five possible outcomes

Do not retry every failure automatically. Consider HTTP semantics, idempotency, authentication and rate limits. Retrying a money transfer without idempotency protection can cause serious problems.
SAY

Success: the server returns valid data. Click through: no network connection, 401 unauthorized, a timeout, and a 500 server error. Each needs a different message and a different next step.

SAY

Do not teach students to retry every failed request automatically. Retries must consider HTTP semantics, idempotency, authentication, rate limits and the business operation.

Part 10 · Background transfers

What happens when the app is backgrounded?

Normal foreground request

Not automatically guaranteed to continue indefinitely once the app is suspended.

Background URLSession

For supported uploads and downloads that must survive suspension or termination, subject to system scheduling.

Background URLSession is not a way to run arbitrary Swift code continuously after the app is suspended.
SAY

A normal foreground URLSession request is not guaranteed to continue indefinitely after the app is backgrounded and suspended. For supported transfers that must survive suspension or even process termination, iOS provides background URLSession configurations, for appropriate uploads and downloads, under system scheduling and restrictions.

SAY

Background URLSession is not a general mechanism for running arbitrary code after suspension.
