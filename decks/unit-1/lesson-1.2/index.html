Can we change the balance?

SAY

let creates a binding that cannot be reassigned after initialization. var creates a mutable variable. Watch the compiler decide.

Part 2 · Reassignment

Same assignment, two keywords

Let.swift
let balance = 25000
balance = 30000
Compiler

ERROR cannot assign to value: ‘balance’ is a ‘let’ constant

Var.swift
var balance = 25000
balance = 30000
Compiles

balance is now ₹30,000

  • Use let unless the value must be reassigned
  • It states intent and blocks accidental changes
  • Careful: let does not always make an object immutable (Part 10)
SAY

The same two lines, once with let and once with var.

SAY

Click: with let, the build fails. The real compiler message: cannot assign to value, balance is a let constant. Click: with var, it compiles and the balance becomes ₹30,000.

SAY

Click: prefer let whenever reassignment is unnecessary. It communicates intent and prevents accidental changes. The compiler even warns when a var is never changed. One subtlety we come back to in Part 10: let does not always mean the whole object is immutable.

Part 3 · Inference

The initial value decides the type

Inference.swift
let name = "Ravi"
let age = 30
let balance = 25000.50
let isActive = true
Initial valueInferred type
"Ravi"String
30Int
25000.50Double
trueBool
Static.swift
var balance = 25000

balance = 30000       // valid
balance = "30000"     // error

ERROR cannot assign value of type ‘String’ to type ‘Int’

  • Types are fixed at compile time
  • Inference only saves typing
  • A variable never changes type at run time
SAY

Four declarations, no types written. The compiler examines the expression that initializes each one: "Ravi" is a String, 30 is an Int, 25000.50 is a Double, true is a Bool.

SAY

Click: inference is not dynamic typing. Once balance is an Int, 30000 is fine, but "30000" is the compile error we met in Lesson 1.1. Swift has static typing with type inference: the compiler decides the type during compilation, and a variable cannot change type at run time.

Part 5 · Money

Double cannot hold 0.1 exactly

Double.swift
let a = 0.1
let b = 0.2

print(a + b == 0.3)
print(a + b)

Prints false, then 0.30000000000000004

Paise.swift
let balanceMinor: Int64 = 2_500_000   // ₹25,000
let transferMinor: Int64 = 25_000     // ₹250

let remaining = balanceMinor - transferMinor
print(remaining)

Prints 2475000: exactly ₹24,750

  • Store whole paise in Int64 (balanceMinor), or use a decimal type
  • Still design overflow, rounding and currency conversion
SAY

Binary floating point cannot represent many decimal fractions exactly; 0.1 and 0.2 are two of them.

ASK

Before the click: does 0.1 + 0.2 equal 0.3?

SAY

Click: false. The sum is 0.30000000000000004. Fine for a graphics coordinate, wrong for a bank balance.

SAY

Click: NPay uses integer minor units. ₹25,000 is 2,500,000 paise in an Int64; subtract a ₹250 transfer and you get exactly 2,475,000 paise, ₹24,750.

SAY

Click: for money, prefer integer minor units or an appropriate decimal type, depending on the domain. Integers remove binary rounding errors, but overflow, rounding rules and currency conversion still need careful design. Lesson 1.10 turns this into a real Money type.

Part 6 · Conversion

Convert on purpose, know what you lose

Convert.swift
let count: Int = 3
let price: Double = 99.5

let total = count * price           // error
let total2 = Double(count) * price  // 298.5

ERROR binary operator ‘*’ cannot be applied to operands of type ‘Int’ and ‘Double’

Truncate.swift
print(Int(3.9))            // 3
print(Int(-3.9))           // -3
print(Int(3.9.rounded()))  // 4
  • Truncates toward zero; it does not round
  • Round first with .rounded() when you mean rounding
SAY

count is an Int, price a Double. count times price does not compile: binary operator star cannot be applied to Int and Double. Convert explicitly, Double(count) times price, and the result is 298.5.

SAY

Click: the other direction. Int(3.9) is 3, and Int(-3.9) is -3: for a finite, representable value, conversion to Int truncates the fractional part toward zero. It does not round. If you mean rounding, say so: Int(3.9.rounded()) is 4.

SAY

Click: the rule. Every conversion is visible in the code, and each one can lose information.

Part 7 · Strings

Interpolation, and what a Character is

Message.swift
let customer = "Ravi"
let balance = 25000

let message =
    "Hello \(customer), your balance is ₹\(balance)"
print(message)

Prints Hello Ravi, your balance is ₹25000

  • \(…) inserts a value’s text into a string
  • Formatting “₹25,000” belongs in the ViewModel (0.2)
Unicode.swift
let flag = "🇮🇳"

print(flag.count)                 // 1 Character
print(flag.unicodeScalars.count)  // 2 Unicode scalars

A Character is an extended grapheme cluster: one or more Unicode scalars.

SAY

Swift uses backslash-parentheses for string interpolation. It inserts a textual representation of an expression into the string: Hello Ravi, your balance is ₹25000. Notice there is no thousands separator; display formatting such as ₹25,000 belongs in the ViewModel, as we said in Lesson 0.2.

SAY

Click: Swift strings are Unicode-aware. The India flag is one Character, but two Unicode scalars, the regional indicators I and N. A Swift Character is an extended grapheme cluster, which can be several scalars. That matters for emoji and for international names: count gives what a person sees as characters.

An array of transaction amounts, a set of payment methods, and a dictionary from customer name to balance. The picture shows how each one organizes its elements.

SAY

Click: arrays preserve order and you access elements by index. Sets store unique elements and do not guarantee any iteration order. Dictionaries map unique keys to values, and a lookup returns an optional, because the key may not exist.

Part 9 · Evidence

No order, and maybe no value

SetOrder.swift
let methods: Set<String> = ["UPI", "CARD", "NEFT"]
print(methods)
RunOutput
1["NEFT", "UPI", "CARD"]
2["CARD", "NEFT", "UPI"]

Same program, different order on each run.

Lookup.swift
var balances = ["Ravi": 25000, "Meena": 18000]

print(balances["Ravi"])   // Optional(25000)
print(balances["Asha"])   // nil
  • A missing key gives nil, not a crash
  • You unwrap the result: Lesson 1.3
SAY

We ran the same Set program twice. The first run printed NEFT, UPI, CARD; the second CARD, NEFT, UPI. Swift randomizes hashing per process, so never rely on a Set’s order; sort it when order matters.

SAY

Click: a dictionary lookup returns an optional. balances["Ravi"] is Optional(25000); balances["Asha"] is nil, because there is no such key. The compiler also warns when you print an optional like this. Lesson 1.3 is all about unwrapping these safely.

Part 10 · let and mutation

A constant reference versus a constant value

ClassAccount.swift
class BankAccount {
    var balance = 25000
}

let account = BankAccount()
account.balance = 30000

Compiles. The reference is constant; the instance is not.

StructAccount.swift
struct BankAccount {
    var balance = 25000
}

let account = BankAccount()
account.balance = 30000

ERROR cannot assign to property: ‘account’ is a ‘let’ constant

SAY

The same five lines; only the first keyword differs, class or struct.

ASK

Before the clicks: which one compiles?

SAY

Click: the class compiles. account is a constant reference to a class instance: we cannot point account at a different instance, but the instance’s mutable properties can still change.

SAY

Click: the struct does not. With a struct, account is the value itself, so a let binding prevents mutating its stored properties. The real message: cannot assign to property, account is a let constant.

CONNECT

Four combinations in one table.

Part 10 · Summary

Reassign versus modify

DeclarationReassign the variable?Modify a var property?
let + structNoNo
var + structYesYes
let + classNoYes
var + classYesYes

Assumes the property is declared var and is accessible.

let fixes the binding. For a class, that binding is a reference, so the instance can still change.
SAY

Read the table row by row. let with a struct: no reassigning, no modifying. var with a struct: both. let with a class: you cannot reassign the reference, but you can modify the instance’s var properties; that is the highlighted row. var with a class: both. This assumes the property is declared var and is accessible.

SAY

Click: the takeaway. This is one of the most important ideas in Swift, and it comes straight from Lesson 1.1: values versus references.

Part 11 · Model

NPay’s first model

BankAccount.swift
struct BankAccount {
    let accountNumber: String
    var balanceMinor: Int64          // paise
    mutating func deposit(_ amountMinor: Int64) {
        guard amountMinor > 0 else { return }
        let (sum, overflow) = balanceMinor.addingReportingOverflow(amountMinor)
        guard !overflow else { return }
        balanceMinor = sum
    }
}
var account = BankAccount(accountNumber: "NP1001", balanceMinor: 2_500_000)
account.deposit(50_000)          // balanceMinor is now 2550000
mutating
  • Needed to change a struct’s stored properties
Guards
  • Only positive deposits
  • Detect overflow, don’t trap
Production
  • Throw errors (1.7)
  • The server processes transactions
SAY

A struct with a constant account number and a variable balance in paise. deposit introduces a new keyword: mutating. A struct method that modifies stored properties must be marked mutating, because it changes the value itself.

SAY

Click: the model checks that the deposit is positive, and uses addingReportingOverflow so an overflow is detected instead of crashing the app. Depositing 50,000 paise, ₹500, gives 2,550,000.

SAY

Click: this is a teaching model. A production banking system would throw explicit errors instead of silently returning, and the server, not the app, processes transactions. Lesson 1.7 covers error handling.

LIVE DEMO

The full model from the lesson text, with customerName and isActive added back: struct BankAccount { let accountNumber: String; let customerName: String; var balanceMinor: Int64; var isActive: Bool; mutating func deposit(_:) as on the slide }. Create var account = BankAccount(accountNumber: "NP1001", customerName: "Ravi", balanceMinor: 2_500_000, isActive: true), call account.deposit(50_000), print(account.balanceMinor) → 2550000. Then change var account to let account and show the compile error on deposit.

Lesson 1.2 · Recap

What to remember

let by default
var only when it must change

Types fixed at build time
inferred, converted explicitly

Money in paise
Int64, never Double

SAY

Three things to remember. Use let by default and var only when the value must change; and remember let on a class fixes the reference, not the instance. Types are fixed at build time: inferred from the initial value, never mixed silently, converted explicitly, and Int(3.9) truncates. And money lives in whole paise in an Int64, never in a Double.
