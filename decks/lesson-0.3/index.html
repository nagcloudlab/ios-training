Part 4 · Three cases

One tap, three possible situations

Cold

New process

Application initialization must happen again.

Warm

Existing process

Application state may already be in memory.

Running

Existing running process

The app can become foreground without being resumed from suspension.

Cold, warm and hot launch are often used informally; their precise meanings vary by performance tool or discussion.

SAY

For teaching, the clearest distinction: a new process means initialization must happen again. An existing process means application state may already be in memory. An existing running process can become foreground without being resumed from suspension.

SAY

The running case: the app is still executing eligible background work. The user brings it forward, the scene transitions through lifecycle states, and foreground interaction resumes, with no process creation or suspension recovery.

SAY

Developers use cold, warm and hot launch informally, and the exact meanings vary by tool. Teach the process distinction rather than the labels.

The mechanism behind this has a name: jetsam.

Part 6 · Jetsam

What is a jetsam termination?

iOS uses memory-management mechanisms commonly called jetsam to terminate processes when it must manage memory pressure.

No resume firstA suspended app can be terminated without being resumed.
No final callbackThe app cannot rely on a last cleanup call.
Next launch rebuildsState may need to be reconstructed.
Foreground apps tooIf their memory use becomes problematic.
Persist important user data at appropriate moments, not when you expect termination.
SAY

Four facts. A suspended app can be terminated without first being resumed. It cannot rely on a final cleanup callback. The next launch may need to reconstruct its state. And foreground apps can also be terminated if their memory use becomes problematic.

SAY

That is why we save important data as we go, not when we think the app is about to end.

How to design for termination

What happens to the form?

Part 7 · Design

The registration form

Poor design

Keep all form data only in memory.

Process termination makes unsaved progress disappear.

Better design

Persist a draft as the user makes progress.

A new process can recover the saved draft.

Process memory is temporary. Durable user data belongs in persistent storage.

SwiftData, files and Keychain serve different purposes. Sensitive information needs protection; not every field belongs in plain preferences.

SAY

The user has entered their name, address and more, then switched apps. Later iOS terminates the app under memory pressure. With the poor design, everything lived only in memory, so the progress is gone. With the better design, a draft was saved as they went, and the new process recovers it.

SAY

SwiftData, files, Keychain and other storage mechanisms serve different purposes. Sensitive information needs appropriate protection; not every field should go in plain preferences.

ASK

EXPECT

Persistent storage, saved as the user goes. Process memory disappears with the process.

Compare the two.

Part 8 · App entry approaches

UIKit vs SwiftUI

UIKit

Delegate-driven approach

Historically UIApplicationDelegate; modern UIKit apps may also use UISceneDelegate.

AppDelegate.swift
class AppDelegate: UIResponder, UIApplicationDelegate {
    func application(_ application: UIApplication,
        didFinishLaunchingWithOptions launchOptions:
            [UIApplication.LaunchOptionsKey: Any]?) -> Bool {
        true
    }
}
SwiftUI

Declarative approach

Defines the application structure declaratively and observes scene lifecycle changes.

NPayApp.swift
@main
struct NPayApp: App {
    @Environment(\.scenePhase) private var scenePhase

    var body: some Scene {
        WindowGroup { Text("NPay") }
            .onChange(of: scenePhase) { _, phase in
                print(phase)
            }
    }
}
SAY

On the left, the system calls the app delegate when launch finishes. On the right, the SwiftUI App declares a WindowGroup and reacts to scenePhase changes; there is no delegate to implement.

SAY

Historically, UIKit apps commonly used UIApplicationDelegate, and modern UIKit apps may also use UISceneDelegate: the system calls delegate methods as the app and its scenes change state. SwiftUI introduced a more declarative way to define application structure and observe scene lifecycle changes.
