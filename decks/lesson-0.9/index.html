SAY

NPay receives this response and shows ₹25,000. Two different things happen: the app holds data in memory to display the screen, and it may persist selected data to storage for later. These are not the same operation.

SAY

RAM is like a classroom whiteboard: convenient for current work, but you cannot assume it survives after the session ends. Persistent storage is a notebook. An app should not rely on process memory for anything that must survive termination.

Part 3 · UserDefaults

Saving a preference

Settings.swift
import Foundation

// Save a preference
UserDefaults.standard.set(
    true,
    forKey: "darkModeEnabled"
)

// Read a preference
let darkMode = UserDefaults.standard.bool(
    forKey: "darkModeEnabled"
)

print(darkMode)
Good for

Selected theme, onboarding completion, preferred language, simple app settings.

Avoid for

Large structured datasets, or as a secure credential store.

SAY

Saving and reading a boolean preference is one line each. UserDefaults suits small settings: theme, onboarding completion, preferred language, simple app settings.

SAY

Avoid it as a database for large structured data, and never as a store for credentials.

Part 4 · SwiftData

A persistent model

SwiftData is not an in-memory array that saves itself. Learn containers, contexts, relationships, schema evolution and save behavior.
TransactionNote.swift
import Foundation
import SwiftData

@Model
final class TransactionNote {
    var title: String
    var amount: Decimal

    init(title: String, amount: Decimal) {
        self.title = title
        self.amount = amount
    }
}
SAY

The SwiftUI screen works through a SwiftData ModelContext, which persists to model storage. @Model marks TransactionNote as a persistent model; SwiftData manages persistence through its model container and context.

SAY

SwiftData is not simply an in-memory array that automatically saves every variable. Developers still need to understand model containers, contexts, relationships, schema evolution and save behavior.

Part 5 · Sandbox directories

Where an app keeps its files

DirectoryTypical purpose
DocumentsUser documents, persistent app files
Application SupportApp-managed support files
CachesRe-creatable cached content
TemporaryShort-lived temporary files
The system can remove cached and temporary content. Don’t treat those directories as permanent.
Statement.swift
import Foundation

let documents = FileManager.default.urls(
    for: .documentDirectory,
    in: .userDomainMask
).first!

let statementURL = documents.appendingPathComponent(
    "statement.pdf"
)

This builds a destination URL; it does not download or write the PDF.

SAY

Apps have directories inside their sandbox. Documents for user documents and persistent files; Application Support for app-managed support files; Caches for content that can be re-created; Temporary for short-lived files. The system can remove cached and temporary content.

SAY

The code asks FileManager for the Documents directory and builds a URL for statement.pdf. It only builds the location; it does not download or write the file.

Part 7 · Termination · conceptual

A draft that may not survive

Persist important data before the app can lose its memory. Do not depend on a final termination callback.

For drafts, save periodically or on meaningful changes, minding performance, security and consistency.

SAY

The user types "Rent payment" as a transfer note. In the first version it exists only in memory: when iOS terminates the process and the user relaunches, it is gone. Click: in the second version the draft was saved, so it comes back.

SAY

Important data should be persisted before the app can lose its in-memory state. Do not rely on a termination callback; save periodically or when meaningful changes happen.

Part 8 · Freshness · conceptual

Cached is not current

Never present stale financial data as current. The backend stays authoritative; local storage improves usability but does not replace server validation.
SAY

The app can show the cached ₹25,000, but it must say it was last updated earlier. Click: the current verified balance is unavailable while offline.

SAY

Communicate data freshness clearly. The backend remains authoritative for balances and transactions; local storage helps usability but does not replace server-side validation.

Part 9 · Comparison

Four persistence technologies

TechnologyWhat it provides
SwiftDataSwift-native persistence framework with model-oriented APIs
Core DataMature object graph management and persistence framework
SQLiteEmbedded relational database engine
FileManagerFilesystem operations, not database object management
New SwiftUI app

SwiftData is often a good start, when its capabilities and deployment targets fit.

Existing or advanced

Core Data remains important for existing apps and advanced requirements.

SAY

SwiftData is a Swift-native framework with model-oriented APIs. Core Data is a mature object-graph and persistence framework. SQLite is an embedded relational database engine. FileManager does filesystem operations, not database object management.

SAY

SwiftData and Core Data can use SQLite-backed stores, but their programming models are not the same as writing SQL. For a new SwiftUI app, SwiftData is often a good start; Core Data remains important for existing apps and advanced needs.
